# 内容数据模型（第一版）

## 项目身份

每个项目应具有不可变 `id` 和 URL 使用的 `slug`；显示名称、别名和历史名称均可以更新。分类只保存稳定分类 ID，不能以项目显示名建立关联。全局别名索引位于 `content/mappings/aliases.json`；项目资料合并、组件归属等关系不应误记为别名，而应记录在资料映射的审查备注中。

## 最小可发布卡片

- 官方项目名称
- 一至两句核心能力简介
- 官方源码入口
- 主要语言
- 支持平台
- 技术路线或核心能力
- 核验状态与日期

## 详情页区块

项目详情将按身份、概览、源码生态、适用范围、理论架构、扩展与数据交换、论文、来源与更新状态组织。每一个区块必须标明 `verified`、`pending` 或 `not_applicable`，避免把待核验内容当作事实发布。

`content/templates/project-detail.json` 是详情资料的字段模板。每个项目的 `project.json` 已预置相同的八个区块及状态；补充资料时先更新区块状态，再填写可由来源支持的字段。

已开始迁入详情的项目在自身目录中维护 `detail.json`。运行 `scripts/build-project-details.js` 后会生成前台读取的 `data/project-details.js`；该生成文件不作为人工编辑入口。

## 来源记录

每条关键事实至少记录来源 URL、来源类型、核验日期、状态和备注。图片额外记录作者/机构、版权或许可证和可公开使用状态。
