# 开源数值仿真项目多维检索种子

> 用途：将本文件完整提供给具备联网检索能力的 AI，用于持续发现、核验和记录可获得源码的数值仿真项目。它是**候选发现种子**，不是正式目录；不得直接修改 `开源数值仿真项目调研目录.md` 或分类规划文件。
>
> 默认语言：中文任务说明 + 中英文检索词。核验日期应由每次执行任务的 AI 填写。

## 0. 调用指令（交给 AI 的任务提示词）

```text
请以《开源数值仿真项目多维检索种子.md》为唯一检索规范，执行一轮“候选发现与核验”。

允许读取：本种子、开源数值仿真导航项目规划.md、开源数值仿真项目调研目录.md、已有的待核验开源项目候选池.md（如存在）。
禁止读取、引用或依赖工作区内已被明确排除的既有深度报告。

必须联网，按“分类坐标 × 数值方法 × 应用领域 × 软件形态 × 补漏维度 × 代码来源平台”交叉检索；不得只按已有二级标题或热门项目检索。许可证、活跃度、星标、项目规模、归档状态和商业支持均不可作为排除条件。

本轮只维护候选池，不修改正式调研目录或分类规划。输出前必须核验每个候选至少有一个可浏览、下载或克隆的源码入口；按官方源码主页去重；已正式收录的项目仅记为“已收录，跳过入池”。
```

## 1. 工作边界与产物

### 1.1 唯一正式归档坐标

- 既有九个一级分类及其二级分类是正式项目库的归档坐标，检索时不得重命名、删除或静默合并。
- 候选项目可归属多个一级/二级分类；多重归属是项目能力的正常表达，而非重复。
- 无法准确归入任一既有二级分类的项目仍必须记录为“其他（待分类）”，并说明盲点；不得因分类不匹配而丢弃。

### 1.2 本轮允许与禁止的写入

| 目标 | 规则 |
| --- | --- |
| `待核验开源项目候选池.md` | 若不存在则首次创建；若存在则增量追加或更新去重状态。 |
| `开源数值仿真项目调研目录.md` | 只读，用于判断已收录项目；本轮禁止修改。 |
| `开源数值仿真导航项目规划.md` | 只读，用于校验分类标题；本轮禁止修改。 |
| 分类体系 | 禁止静默调整；发现系统性盲点只能写入候选池的“分类修订观察”。 |

### 1.3 候选收录门槛

满足下列全部条件即可进入候选池：

1. 与数值仿真、科学计算、工程建模、仿真数据处理或直接相关工作流有明确关系。
2. 至少存在一个可浏览、下载或克隆的源码入口；优先官方仓库、官方发布页或维护机构明确指向的代码页。
3. 能从源码页、官网、文档、论文项目页或可靠机构页识别其基本用途。

不作为排除条件：开源许可证是否明确、仓库是否归档、维护频率、项目规模、语言、星标、是否为教学代码、是否存在商业版本。源码入口暂不能完全确认时，标记“待人工核验”，而不是删除。

```text
"finite element" biomechanics "source code"
"reactive transport" porous media GitHub solver
"Monte Carlo particle transport" open source software
"wind turbine" multibody simulation repository
"phase field fracture" university GitLab
"PDE constrained optimization" scientific computing source code
"CGNS" solver "source code"
"computational geoscience" software paper GitHub
"formerly known as" simulation software source
```

中文、英文和缩写查询应交替使用；对中文结果发现的正式名称，必须再次以英文名/缩写检索；对英文项目，补做中文别名检索以发现国内镜像、实验室分支和中文项目页。

### 4.2 谱系追溯（每个高价值项目至少一次）

发现大型项目、领域平台、软件论文或数值框架后，继续检索：

- 官方组织的全部相关仓库、组织页、发布页和文档引用。
- `depends on`、`built on`、`plugin`、`module`、`adapter`、`coupling`、`examples`、`tutorials`、`applications`、`ecosystem`。
- 同一作者、研究组、实验室、联合体、软件论文作者的项目页与引用软件。
- GitHub/GitLab 的 topics、相关项目、fork network、submodule、release assets 和 archived repositories。
- 论文中的 `code availability`、`software availability`、`supplementary code`、`reproducibility`，以及软件引用、作者其它软件和项目资助页。
- PyPI、conda-forge、Spack、Julia/CRAN 注册表、容器镜像和系统包描述中的 `Homepage`、`Source`、`Repository`、依赖项和维护者。
- 输入/输出格式、插件 API、模型标准、基准数据集、教程课件与 workshop 资料中出现的上下游软件。
- 项目的旧名、早期版本、迁移前的 SourceForge/Bitbucket 仓库、继任项目和分叉谱系。

### 4.3 源码核验与性质判定

每个候选至少核验：

1. 源码链接是否为项目代码、源码压缩包或可克隆仓库，而非新闻页、纯二进制下载页或仅论文页。
2. 链接是否官方；若不能确认，标记为 `镜像`、`fork`、`派生版本` 或 `待人工核验`。
3. 项目是否真正涉及数值仿真/计算工作流；仅使用模拟结果、但不提供相关代码的项目不收录。
4. 能否映射既有分类；能映射时记录全部相关二级标题，不能时进入“其他（待分类）”。

### 4.4 去重与已收录检查

规范化主键优先级：`官方组织/仓库` > `官方源码下载页` > `官方项目主页`。忽略 URL 协议、末尾斜杠、仓库大小写差异后比较。

- 先与正式调研目录比对：已存在同一官方项目时，不写入候选项目表，仅写入本轮日志的“已收录，跳过入池”。
- 再与候选池比对：同一主键合并为一条，补充新分类、发现路径或备用源码链接；不得重复创建项目条目。
- fork、镜像和派生项目不与官方项目混淆：只有产生独立方法、独立维护或独立功能时才单列，并写明上游关系。
- 同名不同项目、同一项目的前端/求解器/模型库拆分仓库，按可独立使用的源码单元记录，并在“关联项目”字段关联。

## 5. 候选池数据接口

首次调用时创建 `待核验开源项目候选池.md`，使用以下固定结构；后续调用只追加、合并或更新状态。


字段规则：

- `来源性质`仅可写：`官方`、`官方发布源码`、`镜像`、`fork`、`派生版本`、`待人工核验`。
- `状态`默认 `待人工核验`；已确认重复则进入“已收录，跳过入池”。
- `建议归属`使用“一级 > 二级”全名，可多个并列；无准确归属写 `其他（待分类）`。
- `数学/方法维度`至少记录离散方法、数学问题或算法范式中的一项；`生态发现入口`记录代码平台、论文、软件包注册表、机构页、标准/数据格式或社区清单中的实际来源。
- `发现查询/路径`必须写出至少一个实际检索组合或谱系路径，保证候选可复查。
- 许可证只记录 `主页明确 + 许可证名`、`仓库可见待人工核验` 或 `未见明确许可证`，不得因其不明而排除。

## 6. “其他（待分类）”兜底规则

满足源码门槛但不能准确归入现有二级标题的项目必须收录。原因至少选择并补充一种：

- 领域专用但方法未公开或方法混合。
- 新兴/混合方法，现有离散方法标题无法准确承接。
- 工作流工具、系统仿真、运行时或耦合环境不属于当前九类。
- 教学、论文复现或算法原型，技术归属待核验。
- 数据、标准、模型库或运行时基础设施。
- 暂无法确认技术归属。

重点观察但不可强行塞入现有分类的方向：多体动力学与系统仿真、蒙特卡洛粒子输运与辐射模拟、化学反应动力学与热力学库、优化/反演/不确定性量化、地理空间/遥感仿真、量子/电子结构计算。只有同类项目持续积累后，才在“分类修订观察”中提出调整建议。

## 7. 质量门禁与干运行验收

### 7.1 每轮结束前检查

- [ ] 九个一级分类和全部二级标题均至少被纳入一次检索组合或谱系追溯。
- [ ] 数值方法、应用领域、软件形态、数学/算法、模型表达、补漏维度、发行渠道、学术/社区生态和代码平台均有实际覆盖记录。
- [ ] 本轮至少有一部分候选来自方法名以外的入口：论文/机构、软件包或容器注册表、标准/数据格式、项目谱系或历史名称。
- [ ] 每个候选均有源码入口、发现路径、来源性质、数学/方法维度、生态发现入口、建议归属或“其他”原因。
- [ ] 候选已与正式目录和候选池按官方源码主键去重。
- [ ] 许可证、归档状态和项目规模未被用作筛除理由。
- [ ] 正式调研目录与分类规划文件未被修改。
- [ ] 没有读取、引用或依赖工作区内被排除的既有深度报告。

## 8. 执行输出模板
