# 项目卡片资料采集规范

本文件只记录一级页面中“项目卡片”需要展示和检索的项目资料。它可作为后续联网搜索、人工核验和数据录入的统一清单；不记录页面布局、分类导航、卡片交互或详情页设计。

## 卡片字段

每个项目按下列字段采集。其中“项目名称、核心能力简介、源码入口”是必填项；其余字段在未核验时明确标记为“待核验”，不要凭经验补全。

| 字段 | 是否必填 | 卡片中的展示方式 | 采集与填写要求 |
| --- | --- | --- | --- |
| 项目名称 | 是 | 卡片标题 | 使用官方项目名；保留官方大小写、连字符和缩写。 |
| 核心能力简介 | 是 | 标题下 1–2 句话 | 一针见血说明项目最突出的用途、技术能力或优势；最多两行。不要复述分类名称，也不要写空泛的“数值仿真软件”。 |
| 源码可得性 | 是 | 标签：`源码可下载` | 确认至少存在一个可浏览、克隆或下载的源码入口后填写。若没有源码入口，不应进入项目卡片库。 |
| 源码入口 | 是 | “直达源代码”按钮链接 | 优先引用《开源数值仿真项目调研目录》中已收录、已核验的源码链接；若目录没有该项目或链接需要更新，再查找官方 GitHub、GitLab、Codeberg、SourceForge、官网源码页或官方发行下载页。记录可直接访问的 URL。 |
| 主要语言 | 是 | 第 2 个标签 | 以官方仓库、官方文档或构建配置为准，例如 `C++`、`Python`、`C++ / Python`。多语言仅列出主要实现或用户可扩展语言。 |
| 支持平台 | 是 | 第 3 个标签 | 记录官方明确支持的运行环境，例如 `Windows / Linux / macOS`、`Linux`、`跨平台`、`Web`。不要由语言反推平台。 |
| 技术路线或核心能力 | 是 | 第 4 个标签 | 使用最具识别度的方法、技术路线或应用能力，例如 `有限元（FEM）`、`有限体积（FVM）`、`相场法`、`CSG / B-Rep`、`并行科学可视化`。每个项目优先只选一个。 |

## 文案标准

### 核心能力简介

- 写“项目能解决什么问题 + 最显著的能力或优势”。
- 使用具体动词，例如“求解”“构建”“耦合”“生成”“可视化”“自动化”。
- 避免宣传语、版本号、星标数、许可证说明和过长的背景介绍。
- 可参考的写法：
  - `以 Python 自动化创建参数化实体模型，并直接输出常用工程交换格式。`
  - `面向大规模有限元分析，提供可扩展的并行求解与自适应网格能力。`
  - `将多源仿真结果组织为交互式三维可视化流程，适合快速分析大规模数据。`

### 标签顺序

卡片最多展示四个标签，顺序固定：

1. `源码可下载`
2. 主要语言
3. 支持平台
4. 技术路线或核心能力

对于尚未完成项目级核验的条目，保留 `源码可下载` 与已确定的技术路线；语言和平台填写 `待核验`，不能用所属分类代替项目事实。

## 搜索与核验提示

### 源码入口的参考来源

《开源数值仿真项目调研目录》是项目卡片源码入口的首要内部参考文件。采集时先按项目名称查找该目录的“项目总索引”及对应分类条目，再复用其中的源码链接。

- 目录中存在官方源码链接：直接采用，并在“信息来源与核验备注”中注明“来源：调研目录”。
- 目录中同时有官网、官方仓库、镜像或 fork：卡片的“直达源代码”优先选择官方源码仓库；官网或文档页可留给后续详情页。
- 目录链接失效、重定向异常或无法确认来源：保留原链接作为线索，但重新检索官方入口，并标记为“待人工核验”。
- 目录中没有该项目：按照下列官方来源顺序完成独立检索后再录入。

为补全单个项目的卡片资料，优先检索以下官方来源：

1. 项目官网与官方文档：用于确认项目定位、支持平台和核心能力。
2. 官方源码仓库的 README、仓库语言统计、构建文件与发布页：用于确认源码入口和主要语言。
3. 官方组织主页、软件论文或机构项目页：用于补充方法路线与项目用途。

建议的检索词组合：

- `[项目名] official source code`
- `[项目名] documentation supported platforms`
- `[项目名] GitHub GitLab source`
- `[项目名] programming language`
- `[项目名] finite element / CFD / visualization / method`

信息冲突时，以项目官网、官方仓库和官方文档为准；无法确认则写 `待核验`，并保留检索到的候选链接供后续人工复核。
