# 开源项目网页内容统一检索规范

本文件是开源数值仿真导航网站的单项目内容采集标准。它统一一级页面项目卡片与二级页面项目详情页所需资料，供后续联网搜索、人工核验、内容录入与页面渲染共同使用。

《一级页面-项目卡片.md》与《二级页面-项目详情.md》保留为原始设计依据；本文件是后续内容工作的唯一字段清单与填写规范。

## 1. 使用原则

### 1.1 资料来源优先级

按以下顺序检索与采用资料：

1. 项目官网、官方文档、官方源码仓库、官方发布页。
2. 官方组织、维护机构、基金会、实验室或开发团队页面。
3. 项目正式发表的软件论文、核心算法论文、官方推荐引用文献。
4. 可靠的包管理页、机构技术报告或同行评议论文；必须标明为“补充来源”。

源码入口优先参考《开源数值仿真项目调研目录》的项目总索引及分类条目。发现失效链接、镜像、fork 或新的官方入口时，保留原链接线索，并在来源备注中说明关系与核验结果。

### 1.2 事实、推断与未知

- 只把可由来源直接支持的信息写为项目事实。
- 由多个来源归纳出的结论标为“综合判断”，并给出依据。
- 无法确认的字段填写 `待核验`；对确实不适用于该项目的理论模块填写 `不适用`。
- 不由项目所属分类、主要语言或相似项目反推平台、算法、功能或成熟度。

### 1.3 图片与版权

- 详情页主图优先选用官网、官方仓库、官方文档或官方论文中明确可复用的界面截图、流程图、架构图或结果图。
- 每张候选图片必须记录：图片 URL、原始页面、作者/机构、版权或许可证、拟使用方式及可否直接发布。
- 版权、授权或许可范围不明确时，填写 `待确认，仅作来源线索`，不得默认下载、裁剪或用于公开网页。
- 图片用于展示软件能力，不替代文字化的功能、理论和证据记录。

## 2. 一级页面：项目卡片字段

卡片只帮助读者快速判断“它是什么、能做什么、是否值得打开详情”。完整背景、功能清单、理论架构和论文只写入详情资料，不在卡片重复展开。

| 字段 | 必填 | 卡片展示方式 | 搜索与填写标准 | 证据要求 |
| --- | --- | --- | --- | --- |
| 官方项目名称 | 是 | 卡片标题 | 使用官方大小写、缩写、连字符与后缀；常用别名不放标题。 | 官方仓库、官网或发布页。 |
| 核心能力简介 | 是 | 标题下 1–2 句 | 写“解决什么问题 + 最突出的能力/优势”；最多两行，避免空泛宣传语。 | 官网简介、README、软件论文。 |
| 源码可得性 | 是 | 标签 `源码可下载` | 至少存在可浏览、克隆或下载的源码入口才填写。 | 可访问的源码入口。 |
| 源码入口 | 是 | `直达源代码` 按钮 | 优先引用《开源数值仿真项目调研目录》中已收录、已核验的源码链接；若目录没有该项目或链接需要更新，再查找官方 GitHub、GitLab、Codeberg、SourceForge、官网源码页或官方发行下载页。记录可直接访问的 URL | 调研目录链接 + 官方页面复核。 |
| 主要语言 | 是 | 第 2 个标签 | 记录主要实现语言或官方支持的核心扩展语言；不列构建脚本等次要语言。 | 仓库语言统计、构建文件、官方开发文档。 |
| 支持平台 | 是 | 第 3 个标签 | 仅记录官方明确支持或测试的平台，如 Windows / Linux / macOS / Web / HPC。 | 安装、下载或构建文档。 |
| 技术路线或核心能力 | 是 | 第 4 个标签 | 选最具识别度的一项，如 FEM、FVM、SPH、CSG / B-Rep、并行科学可视化。 | 官方功能页、论文或开发文档。 |

### 卡片文案规则

- 使用具体动词：`求解`、`构建`、`耦合`、`生成`、`可视化`、`转换`、`自动化`。
- 不写版本号、下载量、星标数、长许可证说明或完整功能清单。
- 标签最多四项，固定顺序为：`源码可下载` → `主要语言` → `支持平台` → `技术路线/核心能力`。
- 示例：`面向大规模有限元分析，提供可扩展的并行求解与自适应网格能力。`

## 3. 二级页面：项目详情字段

### 3.1 项目身份与展示

| 字段 | 必填 | 检索与填写标准 |
| --- | --- | --- |
| 官方项目名称 | 是 | 与卡片标题一致。 |
| 常用别名、缩写与历史名称 | 是 | 记录官网、论文或旧版本中实际使用的名称；无则写 `无`。 |
| 项目类型 | 是 | 如完整求解器、开发库、领域框架、前处理器、后处理器、耦合器、材料库或教学/论文代码。 |
| 当前稳定版本与发布日期 | 是 | 记录最近正式稳定发行版；没有正式发布机制则写 `无稳定版标识`。 |
| 主图资料 | 是 | 按“图片与版权”规则记录候选图、来源、授权状态与建议用途。 |
| 一句话定位 | 是 | 比卡片简介稍完整，概括项目角色、方法与主要应用边界。 |

### 3.2 项目概览与问题解决能力

| 字段 | 必填 | 检索与填写标准 |
| --- | --- | --- |
| 项目解决的问题 | 是 | 描述研究或工程问题，而不是只复述软件类型。 |
| 目标用户 | 是 | 如研究人员、工程分析人员、软件开发者、教育用户、领域科学家。 |
| 典型应用领域 | 是 | 记录官方示例、案例或论文实际涉及的领域。 |
| 核心特色 | 是 | 给出 3–5 项可证实的差异化能力。 |
| 可处理物理过程 | 是 | 如结构、流体、传热、电磁、声学、化学、颗粒、分子或多物理场；不适用则说明原因。 |
| 分析对象与结构类型 | 是 | 如实体、壳、梁、颗粒、网格、点云、血管、裂隙、分子等。 |
| 分析类型与规模 | 是 | 如稳态/瞬态、线性/非线性、显式/隐式、串行/并行、大规模；仅列官方明确能力。 |
| 主要输入与输出 | 是 | 输入模型、网格、材料、边界条件、脚本、数据格式；输出结果、日志、可视化或交换格式。 |
| 典型研究与工程用途 | 是 | 从案例、教程、论文中归纳 2–5 项，并区分事实与综合判断。 |

### 3.3 源代码、生态与社区

| 字段 | 必填 | 检索与填写标准 |
| --- | --- | --- |
| 官方源码入口 | 是 | 记录主仓库、源代码下载页、镜像/fork 关系与可访问性。 |
| 官网与官方文档 | 是 | 分别给出 URL；没有官网时说明以仓库文档为主。 |
| 下载/发行页 | 是 | 记录 Release、包管理、容器、二进制或源码发行入口。 |
| 许可证 | 是 | 记录 SPDX 名称或官方许可证文本；不以第三方网站推断。 |
| 安装与依赖 | 是 | 记录关键依赖、安装方式、支持平台及硬件要求。 |
| 社区入口 | 是 | 记录论坛、邮件列表、讨论区、Issue、聊天室、用户组或培训资料。 |
| 插件、适配器与下游生态 | 是 | 记录官方插件、绑定、耦合器、模型库、示例库或主要下游项目。 |
| 维护组织与主要开发者 | 是 | 记录维护机构、官方组织、核心开发团队；避免推测个人角色。 |
| 发展沿革 | 是 | 记录起源、重要改名/重构、关键版本或维护权转移。 |
| 成熟度与维护状态 | 是 | 依据最近发行、提交、Issue 响应、文档和社区活动作“综合判断”，注明核验日期。 |

## 4. 理论架构与计算流程

本节应逐步说明项目从输入到结果的理论和软件能力，帮助读者判断其中是否包含可学习、可复用或可扩展的内容。以下字段均需检索；未涉及时写 `不适用`，资料不足时写 `待核验`。

| 模块 | 要搜索的内容 |
| --- | --- |
| 物理与控制方程 | 控制方程、守恒律、弱式/强式、物理模块、假设与适用范围。 |
| 离散与数值方法 | FEM、FVM、FDM、DG、BEM、谱方法、SPH、DEM、MPM、PIC、LBM、相场、近场、蒙特卡洛等；记录具体变体。 |
| 几何、网格与前处理 | CAD/几何内核、网格类型、网格生成、质量控制、自适应、分区、模型装配和格式导入。 |
| 单元、粒子或离散对象 | 单元族、维度、形函数、积分、稳定化、沙漏控制、粒子核、接触对象、网格层级等。 |
| 材料、本构与模型库 | 线弹性、塑性、超弹性、粘弹性、损伤、晶体塑性、流变、反应动力学、势函数及用户自定义接口。 |
| 初始、边界与载荷 | Dirichlet、Neumann、Robin、周期、接触、界面、初值、体力、热源、流入流出等实现方式。 |
| 线性与非线性求解 | 直接/迭代求解器、Krylov 方法、预条件、多重网格、Newton、弧长法、残差/收敛控制。 |
| 时间推进与事件处理 | 稳态、显式/隐式、时间积分格式、自适应步长、子循环、重启动、事件或断裂演化。 |
| 多物理场与多尺度耦合 | 单体/分区耦合、场交换、FE²、FSI、热-结构、化学-热-力、原子-连续体等。 |
| 并行与硬件加速 | MPI、OpenMP、GPU、CUDA、HIP、SYCL、任务并行、负载均衡、并行 I/O 与性能可移植。 |
| 后处理与数据交换 | 结果变量、输出格式、可视化接口、数据转换、Python/脚本 API、批量分析。 |
| 扩展与二次开发 | 插件机制、用户子程序、材料接口、C/C++/Python/Julia 等 API、DSL、模型与示例库。 |
| 已知限制与适用边界 | 官方列出的不支持功能、平台限制、规模限制、实验性模块、版本兼容性和依赖约束。 |

## 5. 论文与学术证据

每个项目都应检索软件引用论文、理论基础、关键算法实现和应用验证文献。没有公开论文的项目写 `未检索到正式论文`，同时保留仓库、文档或技术报告作为替代证据。

### 文献类别

1. 软件/项目引用论文：项目总体设计、架构、引用方式或版本说明。
2. 核心理论论文：代码所依据的离散、模型或数学理论。
3. 关键算法论文：并行、求解器、网格、耦合、材料或数据处理等重要实现。
4. 应用验证论文：典型领域的验证、基准或实际工程/科研应用。

### 每篇论文的记录字段

- 完整参考文献：作者、题名、期刊/会议/出版社、年份、卷期页码。
- DOI、arXiv、机构存档或正式网页链接。
- 作者与机构信息（以论文或官方项目页为准）。
- 摘要要点：用自己的话概括研究对象、方法与主要结论，不大段复制摘要。
- 与项目的关系：软件整体介绍、理论来源、算法实现依据、验证证据或应用案例。
- 对理论架构的意义：仅对基础性文献说明其影响的模块与原因。

## 6. 检索工作流与核验记录

### 6.1 推荐检索顺序

1. 在《开源数值仿真项目调研目录》中查找项目名、源码入口和全部分类归属。
2. 访问官方仓库 README、发行页、构建文件和 `CITATION`/`README`/`LICENSE` 文件。
3. 访问官网、安装文档、功能页、教程、示例与 API 文档。
4. 检索官方推荐论文、项目 DOI、软件引用页和可靠学术数据库。
5. 核验图片来源、授权状态、社区入口和维护状态。
6. 将每项信息填入单项目模板，并在来源表中记录 URL、来源类型、核验日期与状态。

### 6.2 常用检索词

- `[项目名] official source code`
- `[项目名] documentation installation supported platforms`
- `[项目名] license release GitHub GitLab`
- `[项目名] citation paper DOI`
- `[项目名] theory numerical method solver`
- `[项目名] mesh material model boundary condition`
- `[项目名] parallel GPU MPI extension API`
- `[项目名] official screenshot architecture diagram license`

### 6.3 核验状态

| 状态 | 含义 |
| --- | --- |
| 已核验 | 有直接且可访问的官方或可靠来源支持。 |
| 补充来源 | 信息来自可靠但非官方来源，需在备注中写明。 |
| 待人工核验 | 已发现候选信息或链接，但归属、时效或许可尚未确认。 |
| 待核验 | 尚未找到足以支持该字段的资料。 |
| 不适用 | 该字段不适用于当前项目类型。 |

## 8. 发布前自检

- 卡片内容是否只保留名称、能力简介、四项标签与源码入口，不重复详情材料？
- 详情页是否说明了问题解决能力、理论架构、代码生态和学术证据？
- 每项事实是否能回溯至来源记录？
- 主要语言、平台、算法、许可证和维护状态是否避免了未经证实的推断？
- 图片是否有可追溯来源，并明确网页使用授权状态？
- 不同软件形态是否正确使用“待核验”或“不适用”，而非强行填写相同理论模块？
